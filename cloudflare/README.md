# ☁️ إعداد Cloudflare — الوسيط المركزي للتطبيق

التطبيق عند كل تشغيل يسأل **رابطاً واحداً ثابتاً** على Cloudflare عن شيئين:

1. **مفاتيح قاعدة البيانات** الحالية (Supabase أو أي منصة أخرى تختارها أنت)
2. **آخر إصدار من التطبيق** + رابط تحميله (للتحديث الذاتي)

أنت تتحكم في الاثنين من ملف واحد: [`worker.js`](worker.js) — وكل الأجهزة تتبع أي تغيير تلقائياً
خلال دقيقة واحدة على الأكثر، **بدون تحديث التطبيق من المتجر**.

---

## 🛠 الخطوة ١: إنشاء العامل (مرة واحدة — 5 دقائق)

1. سجّل حساباً مجانياً في [cloudflare.com](https://cloudflare.com)
2. من القائمة الجانبية: **Workers & Pages** ← **Create** ← **Create Worker**
3. اختر اسماً مثل `mr-center-config` ← اضغط **Deploy**
4. اضغط **Edit code** ← احذف الكود الموجود ← الصق كامل محتوى [`worker.js`](worker.js)
5. عدّل القسمين في أعلى الملف:
   - `DATABASE` ← رابط مشروع Supabase ومفتاح anon (نفس مفاتيح موقعك)
   - `UPDATE` ← اتركها كما هي الآن، سنرجع لها عند أول تحديث
6. اضغط **Deploy**
7. انسخ رابط العامل، سيكون شكله:
   ```
   https://mr-center-config.<اسم-حسابك>.workers.dev
   ```
   رابط الاستعلام الكامل: **`https://mr-center-config.<اسم-حسابك>.workers.dev/config`**

8. **ضع هذا الرابط في التطبيق قبل البناء**: افتح `app.json` ← حقل `extra.configUrl`

جرّب الرابط في المتصفح — يجب أن تظهر JSON فيها database و update.

---

## 📦 الخطوة ٢: استضافة ملفات APK (للتحديثات) عبر R2

ملفات APK أكبر من أن تخدمها Worker مباشرة — نستخدم **تخزين R2** (مجاني حتى 10GB وبدون رسوم تحميل):

1. من لوحة Cloudflare: **R2 Object Storage** ← **Create bucket** ← اسم مثل `mr-center-app`
2. افتح الـ bucket ← **Settings** ← فعّل **Public access** (أو اربط دومين مخصص إن أردت)
3. انسخ **الرابط العام للـ bucket** (Public R2.dev URL)، شكله:
   `https://pub-xxxx.r2.dev`
4. عند كل إصدار جديد: ارفع ملف APK باسم ثابت مثل `mr-center.apk` ←
   رابطه يصبح `https://pub-xxxx.r2.dev/mr-center.apk` ← ضعه في `UPDATE.apk_url` في العامل

> 💡 الاسم الثابت يعني أن رابط التحميل لا يتغير أبداً — ترفع ملفاً جديداً مكان القديم فقط.

---

## 🔄 دورة إصدار تحديث جديد للتطبيق (كاملة)

1. عدّل رقم الإصدار في `app.json`: `"version": "1.0.1"` وزد `"versionCode": 2`
2. ابنِ الـ APK: `eas build --platform android --profile preview`
3. حمّل الملف الناتج وارفعه إلى R2 باسم `mr-center.apk` (يستبدل القديم)
4. عدّل `worker.js` ← قسم `UPDATE`:
   ```js
   latest_version: "1.0.1",
   version_code: 2,
   changelog: "ما الجديد في هذا الإصدار...",
   ```
5. **Deploy** للعامل → خلال دقيقة واحدة، كل جهاز يفتح التطبيق سيظهر له:
   **«يوجد إصدار جديد 1.0.1»** ← «تحديث الآن» ← يُحمَّل ويُثبَّت فوق القديم تلقائياً.
6. لو التحديث ضروري ولا يصح الاستمرار بدونه: اجعل `force_update: true` فيظهر حاجز إجباري.

---

## 🔀 تغيير قاعدة البيانات لمنصة أخرى مستقبلاً

عدّل قسم `DATABASE` في العامل بالرابط والمفتاح الجديدين ← Deploy ← كل الأجهزة
تلتقط الجديد عند أول تشغيل. (طبعاً يجب أن توجد نفس الجداول والدوال في القاعدة الجديدة —
شغّل ملف `supabase/android_multitenant_schema.sql` عليها إن كانت Supabase جديد،
أو ما يكافئه في المنصة الأخرى.)

---

## 🔐 ملاحظات أمنية

- العامل يعرض مفتاح `anon` العام فقط — وهذا **آمن** لأن الحماية الحقيقية في سياسات RLS
  بقاعدة البيانات (نفس مبدأ موقع الويب الحالي الذي يعرض المفتاح في متصفح الزائر).
- **لا تضع أبداً** مفتاح `service_role` أو كلمة مرور قاعدة البيانات في العامل.
- من أراد تعطيل التحقق من التحديث مؤقتاً: اجعل `version_code` مساوياً لرقم النسخة المنشورة.
